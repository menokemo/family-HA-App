> تطبيق Android لإدارة Home Assistant، مركّز على Alarmo وأمان العائلة
> والكاميرات والخريطة. المطوّر: **MKDD**.
>
> ده تعريف المشروع عالي المستوى. التفاصيل التقنية الحيّة في الريبو:
> `PROJECT_SUMMARY.md` (الحالة الحالية)، `CHANGELOG.md` (كل إصدار)،
> `BUGS_AND_FIXES.md` (كل مشكلة وسببها الجذري وحلّها).
>
> الاسم التجاري/الباقة: **Secure Family** (داخليًا `com.mkdd.familyha`).

------------------------------------------------------------------------

# فكرة المشروع

تطبيق عائلي يشتغل مع Home Assistant **محليًا بالكامل** (بدون سحابة). الفرد
التقني بيظبط كل حاجة مرة واحدة وينشرها، وباقي العيلة بيثبّتوا التطبيق ويدخلوا بس.

المشروع جزئين:

1.  **التطبيق** (React Native / TypeScript, bare CLI, RN 0.83 + New
    Architecture + Hermes).
2.  **مكوّن Home Assistant مخصّص** (`secure_family`, Python, HACS) — مخزن
    الإعداد المركزي + إدارة أجهزة التطبيق + التنظيف التلقائي. ريبو منفصل
    (`secure-family-dmkd`) بيتسلّم كـ ZIP ويترفع عبر HACS.

# الوظائف

## 1. Home Assistant

-   الاتصال بعنوان السيرفر، دعم OAuth والـ Long-Lived Token.
-   العنوان بيتطبّع تلقائيًا (http/https) فمايتبوّظش الدخول.

## 2. Alarmo

-   الحالة، Arm/Disarm، PIN لكل مستخدم، كل بيانات Alarmo، أحداث WebSocket،
    صوت الإنذار، أسباب فشل التسليح بأسماء Friendly.

## 3. الكاميرات

-   قائمة Snapshots، شاشة مستقلة، Live Stream بأولوية WebRTC → HLS → MJPEG →
    Snapshot.

## 4. الخريطة

-   نسختين: **ويب** (WebView + MapLibre GL JS) و**نيتف** (MapLibre React Native
    v11 — أنعم وأسرع، خلف مفتاح تبديل، الويب fallback).
-   بلاطات OpenFreeMap مجانية + قمر صناعي Esri، أفراد العائلة بصورهم، المناطق
    كدوائر، طبقة المخاطر (`geo_location`)، البطارية/الدقة/المسافة.
-   **علامة "أنا" موحّدة** عند الموقع الحي (Fused) بدل علامتين.
-   الموقع الحي عند الطلب، وزر Navigate.

## 5. الإعدادات

-   التطبيق (السيرفر، اللغة، صوت الإنذار)، Alarmo، الكاميرات، الخريطة
    (مفتاح النيتف)، "هذا الجهاز" (اسم الجهاز، إعادة تسجيل).

## 6. الأمان

-   PIN + بصمة + تخزين آمن (Keychain).
-   **جهاز نشط واحد لكل مستخدم:** معرّف ثابت للموبايل؛ أول/نفس الموبايل =
    تسجيل مباشر (صفر تكرار)؛ موبايل جديد والحساب نشط = نافذة استبدال + موافقة
    أدمن بكود سرّي (10 دقايق، مرة واحدة، عبر خدمة أدمن محصورة — مش مبثوث).
    عند الموافقة الجهاز القديم يتمسح ويخرج فورًا.

## 7. الإشعارات

-   Push محلي، صوت عند Trigger، تنبيه دخول/خروج المناطق، تنبيه فتح باب أثناء
    التسليح.

## 8. Offline First

-   حفظ آخر حالة Alarmo، أحداث، Snapshots، مواقع.

# المكوّن (Home Assistant Integration — `secure_family`)

-   **مخزن الإعداد المركزي** (نشر/استرجاع/مسح الإعداد، بإصدارات).
-   **أجهزة التطبيق:** `sensor.secure_family_devices` بيسرد تليفونات تطبيقنا
    (مفلتر بـ `app_id: secure_family` — مابيلمسش التطبيق الرسمي).
-   **إدارة التسجيل:** خدمات `request_registration` / `approve_registration` /
    `deny_registration` / `list_pending_registrations` (جهاز واحد لكل مستخدم +
    موافقة أدمن). أحداث: `familyha_force_logout` / `familyha_device_approved` /
    `familyha_device_approval`.
-   **التنظيف التلقائي:** يشيل التكرارات/القديم ويمسح إحصائياتها (منع تحذيرات
    "entity has no state") — كل بضع ساعات وبعد البدء.
-   **الموقع الحي عند الطلب:** `request_live_location`.
-   كود منظّم في موديولات صغيرة: `devices.py` + `device_store.py` + `store.py`.

# دروس مهمة اتكشفت أثناء التطوير

-   **الموقع لازم يكون Fused (Play Services) زي Find Hub** — مش GPS الخام ولا
    `lastLocation` المخبّأ (اللي ممكن يرجّع موقع بعيد). استخدم
    `setRNConfiguration({locationProvider:'playServices'})` و
    `getCurrentLocation(HIGH_ACCURACY)`.
-   **metro في RN 0.83 مفعّل `unstable_enablePackageExports`** — بعض المكتبات
    لازم `require` (CommonJS) مش `import` عشان ماترجعش undefined.
-   **HA بيعمل جهاز جديد مع كل `POST /registrations`**، و`update_registration`
    مابيعيدش التسمية بموثوقية — فجهاز واحد نشط لكل مستخدم هو الحل الجذري للتكرار.
-   **أسرار (أكواد) مينفعش تتبعت في أحداث HA أو الإشعارات الثابتة** لأنها مبثوثة
    للكل — لازم خدمة محصورة على الأدمن.
-   الاعتماد على خدمات مجانية/مفتوحة المصدر بدون مفاتيح API أفضل لما يكون ممكن.
-   Expo Go مايدعمش WebRTC النيتف؛ RN CLI / Development Build أنسب.
